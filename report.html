1 Overview

A Spring Boot (Java 17, Maven) calculator service exposes /api/v1/add, subtract, multiply, divide and the Actuator endpoint /actuator/health. Invalid or missing parameters and division by zero return HTTP 400 with a structured JSON error.

  • GitHub Repository: https://github.com/Venkat96r/calculator-devops
  • Docker Hub Repository: https://hub.docker.com/r/venkat96r/calculator-api
  • Tools in Scope: Git/GitHub, Jenkins (declarative pipeline), Docker (multi-stage image), Docker Compose with Nginx.

2 Pipeline Architecture

Figure 1. Pipeline architecture. A push to main triggers SCM polling; Jenkins runs the six stages and e-mails the result; the image is published to Docker Hub and deployed as an Nginx-fronted, two-replica Compose stack.

3 Pipeline Stages

Stage Description
Checkout checkout scm pulls the latest commit. The job is triggered automatically by SCM polling (pollSCM('* * * * *')).
Build mvn -B clean package -DskipTests compiles the Java 17 code and produces the executable JAR target/calculator.jar.
Test mvn -B test executes the 5 JUnit 5 unit tests and 7 MockMvc integration tests. The junit step publishes target/surefire-reports/*.xml; a failing test halts the pipeline.
Docker Build Builds the multi-stage image (Maven/JDK 17 builder with dependency offline cache, slim JRE 17 Alpine runtime, non-root user app:100, EXPOSE 8080) and tags it with ${BUILD_NUMBER} and latest.
Push Logs in with withCredentials using Jenkins credential docker-cred, pipes credentials through docker login --password-stdin, pushes both tags, and logs out in a post block. No secret is saved in repository or logged.
Deploy docker compose pull && docker compose up -d --remove-orphans starts Nginx and two replicas, then polls /actuator/health through the proxy (up to 100 s) and fails the build if the stack never reports UP.
Notify The pipeline post block dispatches an automated SUCCESS or FAILURE email with the build URL.

Idempotency. Re-running with the same image tag leaves all containers untouched; a new tag recreates only the calculator replicas, and the health check still passes. Both cases were verified repeatedly across pipeline executions.

Compose design. The stack declares a named bridge network (calc-net), a health check on /actuator/health, restart: unless-stopped, environment variables, and depends_on with condition: service_healthy so Nginx starts only after the API is ready. The proxy host port is mapped to 8081 (avoiding Jenkins port 8080), and the image tag is dynamically injected (IMAGE_TAG).

Version control. Work was done progressively on feature branches and merged with --no-ff: feature/calculator-api, feature/docker, and feature/jenkins-pipeline, using conventional commit messages. .gitignore excludes build outputs, IDE files, and secrets.

4 Challenges Faced

  • Nginx was not load balancing across replicas. Docker DNS returned both replica addresses, yet an access log showed traffic sticking to a single replica because standard Nginx resolves hostnames once during startup. Using Docker’s embedded resolver (127.0.0.11 valid=10s;) with a runtime variable in proxy_pass (set $upstream http://app:8080; proxy_pass $upstream;) makes Nginx resolve dynamically per request; traffic is evenly distributed across both replicas and recreated containers are picked up without restarting Nginx.
  • Port clash with Jenkins. Jenkins and the proxy both default to port 8080. Exposing the Spring Boot service directly on 8080 caused socket binding collisions. The application was kept inside the Docker bridge network on port 8080 and Nginx was mapped externally to port 8081 (8081:80); the Compose project name is pinned (calculator) so it remains independent of the Jenkins workspace folder.
  • Cross-Platform Jenkins execution on Windows Host. The local Jenkins service runs on Windows under Local System, which lacks POSIX sh.exe and user environment variables. Implementing cross-platform step branching (isUnix()), explicitly injecting JAVA_HOME and Maven into the pipeline PATH, and resolving PowerShell embedded regex quotes in the healthcheck loop allowed the pipeline to execute natively on Windows while remaining 100% portable to Linux agents.
  • Automated triggering without public webhooks. GitHub webhooks require a publicly exposed URL (e.g. via ngrok). To keep the pipeline self-contained without third-party tunnels or external open ports, Jenkins SCM Polling (pollSCM('* * * * *')) was configured to query GitHub every minute, reliably triggering builds on push.
